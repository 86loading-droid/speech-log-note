# 발화 기록 노트 (Speech Log for Special Education)

학생이 말하면 실시간으로 텍스트가 입력되고, **날짜·시각·말하는 사람(화자)·기록하는 사람(기록자)** 정보와 함께 저장되는 단일 파일 웹 애플리케이션입니다.
태블릿PC를 기준 기기로 설계했으며 휴대폰·데스크톱에서도 동일하게 동작합니다.

---

## 1. 주요 기능

| 구분 | 내용 |
|---|---|
| 가로 화면 배치 | 태블릿을 눕히면 자막이 화면 전체 폭을 쓰고 버튼은 모두 화면 하단에 모입니다. 자막이 화면 높이의 약 60%(1280×800), 전체화면 버튼을 누르면 약 71%를 차지합니다 |
| 전체화면형 기록 화면 | 첫 화면 전체가 자막 영역입니다. 기록 목록은 목록 탭으로 분리했고, 전체화면 버튼을 누르면 상단 막대와 탭까지 감춰 글자만 남습니다 |
| 누르고 말하기 | 마이크 버튼을 누르고 있는 동안만 녹음됩니다. 손을 떼면 멈추고 글자는 화면에 남습니다. 주변 소음과 교사의 말이 섞이지 않습니다 |
| 기록 전 확인 절차 | 읽어주기 → 수정 → 기록하기 순서로 학생과 함께 확인한 뒤 저장합니다 |
| 내 목소리 듣기 | 학생이 방금 말한 소리를 그대로 들려줍니다. 기계 음성은 쓰지 않습니다 |
| 천천히 반복 | 같은 목소리를 느린 속도(기본 0.7배)로 반복해 들려줍니다. 목소리 높낮이는 유지하고 속도만 늦춥니다. 반복 횟수 기본 10회 |
| 낱말 고르기 | 방금 녹음에서 학생이 바르게 낸 한 낱말만 구간으로 잘라 모델로 남깁니다. 합성이 아니라 학생의 실제 발화이므로 자기 모델링 근거가 그대로 적용됩니다 |
| 낱말·음절 모델 | 녹음에서 낱말을 잘라 저장하고, 필요하면 음절 단위로 더 쪼개 저장합니다. 음절을 모아 두면 처음 보는 낱말도 읽을 수 있습니다 |
| 이어 읽기 (연결 합성) | 큰 화면에 있는 글을 학생이 실제로 낸 소리로 읽어 줍니다. 낱말 모델을 먼저 쓰고 없으면 음절을 이어 붙여 문장 전체를 한 덩어리로 합성해 재생합니다. 신경망 합성을 쓰지 않으므로 비용과 외부 전송이 없습니다 |
| 낱말 모델 | 저장한 낱말을 학생별로 묶어 보여 주고 듣기·천천히로 다시 듣습니다. 남은 보관 시간이 항목마다 표시되며 1시간 뒤 자동으로 지워집니다 |
| 목소리 녹음 | 마이크를 누르고 있는 동안의 학생 음성을 함께 담아, 듣기 버튼으로 바로 재생합니다. 파일로 내보내지 않으며 보관 시간이 지나면 자동 삭제됩니다 |
| 목소리 녹음 버튼 | 누르고 있는 동안 글자 인식 없이 목소리만 담습니다. 큰 표시와 레벨 막대로 소리가 들어오는 것을 보여 주며, 담은 소리는 듣기·천천히 반복·낱말 고르기·이어 읽기에 그대로 쓰입니다 |
| 화자별 녹음 설정 | 학생마다 녹음을 켜고 끕니다. 꺼진 학생은 말하기에서도 목소리가 담기지 않고 글자만 기록됩니다 |
| 음성 입력 | Web Speech API(`SpeechRecognition`) 기반 실시간 인식. 중간 인식 결과는 회색, 확정 결과는 진하게 표시 |
| 발화 유지 | 한 문장이 끝나도 글자가 화면에서 사라지지 않습니다. 다음 발화가 확인되는 순간 앞 발화가 기록으로 넘어가고 새 문장이 자리를 대신합니다. 상태 배지로 기록 대기 / 기록됨을 구분 |
| 유지 시간 상한 | 다음 발화가 없어도 설정한 시간(기본 30초)이 지나면 자동으로 기록됩니다. 배지에 남은 초가 표시되고 게이지가 줄어듭니다. 10 / 20 / 30 / 45 / 60초 또는 제한 없음 |
| 교정 사전 | 반복해서 잘못 인식되는 낱말을 "잘못 인식되는 말 → 올바른 말" 규칙으로 등록하면 인식 결과에 자동 적용됩니다. 바뀌기 전 인식 원문을 함께 보관 |
| 인식률 분석 | 자동 교정이 적용된 발화 비율, 교사가 손으로 고친 발화 비율, 규칙별 적용 횟수와 마지막 적용일을 집계 |
| 메타데이터 | 기록마다 날짜, 시각(초 단위), 화자, 기록자, 입력 방식(음성/직접 입력), 글자 수, 수정 여부 자동 저장 |
| 글자 크기 | 12pt ~ **100pt** 슬라이더 + 24/40/60/80/100pt 원터치 프리셋. PPT 포인트 기준 그대로 표기하고 px 환산값 병기 (1pt = 4/3 px) |
| 접근성 | 밝은 화면 / 어두운 화면 / 고대비(검정-노랑) / 고대비(흰색-검정) 4종 테마, 최소 44px 터치 영역, `aria-live` 실시간 안내 |
| 편집 | 인식 오류 즉시 수정, 개별 삭제, 복사 |
| 대체 입력 | 키보드 직접 입력 병행 (음성 인식이 어려운 학생 대응) |
| 통계 | 화자별 발화 횟수·총 글자 수·평균 길이·최장 발화, 시간대별 분포, 날짜별 집계 |
| 내보내기 | CSV(엑셀 호환, UTF-8 BOM) / JSON(재가져오기 가능) / TXT(전사본), 클립보드 복사 |
| 기타 | 녹음 중 화면 꺼짐 방지(Wake Lock), 인식 중단 시 자동 재시작, 스페이스바 단축키 |

## 2. 저장 구조

기록은 **이 기기의 브라우저 안에만** 저장됩니다. 외부 서버로 전송되지 않습니다.

```
localStorage
├─ sttlog.records.v1   // 발화 기록 배열
└─ sttlog.settings.v1  // 기록자명, 화자 목록, 글자 크기, 테마, 언어
```

기록 1건의 구조:

```json
{
  "id": "m3k9x2a7b1",
  "ts": "2026-09-12T09:14:32.118Z",
  "date": "2026-09-12",
  "time": "18:14:32",
  "speaker": "김민준",
  "recorder": "최현석 교사",
  "text": "오늘 체육 시간에 축구를 했어요.",
  "source": "voice",
  "chars": 16,
  "edited": false
}
```

> **중요** — 브라우저 데이터 삭제, 기기 교체, 시크릿 모드 종료 시 기록이 사라집니다.
> 수업 종료 시마다 **JSON 또는 CSV로 내보내기**를 하는 절차를 운영 규칙으로 정해 두십시오.

## 3. 저장소 구성

```
speech-log/
├─ index.html          # 애플리케이션 전체 (HTML + CSS + JS 단일 파일, 외부 의존성 없음)
├─ README.md           # 이 문서
├─ worker.js           # (미사용) 음성 복제 중계 서버 — 유료 전환 검토용 보관
└─ wrangler.toml       # (미사용) 중계 서버 배포 설정
```

앱 자체에는 외부 라이브러리·빌드 도구·서버가 전혀 없습니다. `index.html` 하나만 있으면 동작합니다. `worker.js` 와 `wrangler.toml` 은 현재 쓰이지 않습니다. 6-5에 적은 유료 전환을 검토하실 때를 위해 남겨 둔 파일이며, 배포에 영향을 주지 않습니다.

## 5. 배포 — GitHub Pages (무료·HTTPS 자동)

1. 저장소 → **Settings** → 왼쪽 메뉴 **Pages**
2. *Build and deployment* → Source: **Deploy from a branch**
3. Branch: `main` / 폴더: `/ (root)` → **Save**
4. 1~2분 후 상단에 주소가 표시됩니다.

```
https://<사용자명>.github.io/speech-log/
```

이 주소는 **https** 이므로 마이크 권한 요청이 정상 동작합니다.

## 6. 브라우저·기기 호환성

`SpeechRecognition` 은 브라우저 내장 기능이므로 기기별 지원 범위를 먼저 확인하십시오.

이 앱의 지원 대상은 갤럭시(안드로이드) 태블릿의 Chrome 입니다. 아이패드와 아이폰은 지원하지 않습니다.

| 기기 / 브라우저 | 지원 | 비고 |
|---|---|---|
| 갤럭시 태블릿 · Chrome (가로) | 지원 대상 | 기준 환경. 눕혀서 쓰는 것을 전제로 배치했습니다 |
| 안드로이드 휴대폰 · Chrome | 동작 | 화면이 좁아 자막 영역이 줄어듦 |
| Windows · Chrome / Edge | 동작 | 수업 전 준비·검토용 |
| iPad · iPhone | 지원하지 않음 | 접속하면 안내 배너가 뜹니다. 인식과 녹음이 마이크를 동시에 잡을 때 불안정합니다 |
| Firefox | 지원하지 않음 | 음성 인식 미지원. 수정 버튼의 키보드 입력만 가능 |

지원 대상이 아닌 환경에서는 화면 상단에 안내 배너가 뜨고, 수정 버튼의 키보드 입력으로 동일한 형식의 기록을 남길 수 있습니다.

### 동작 조건 점검표

- [ ] 주소가 `https://` 로 시작하는가 (또는 `localhost`)
- [ ] 브라우저 마이크 권한이 **허용** 상태인가 (주소창 자물쇠 아이콘에서 확인)
- [ ] 다른 앱(화상회의, 녹음기)이 마이크를 점유하고 있지 않은가
- [ ] 기기가 인터넷에 연결되어 있는가 (브라우저 음성 인식은 서버 처리 방식)

## 7. 수업 현장 운영 절차

1. **수업 전** — 설정에서 기록자 이름 입력, 학생 명단(화자) 등록
2. **화자 선택** — 발화 직전에 상단 칩에서 해당 학생을 누른다. 학급 인원 10명까지는 스크롤 없이 한눈에 보입니다
3. **누르고 말하기** — 마이크 버튼을 누른 채로 학생이 말하게 하고, 말이 끝나면 손을 뗀다. 글자는 화면에 그대로 남는다
4. **함께 확인** — 학생과 화면의 문장을 읽는다. 읽어주기를 누르면 학생이 방금 말한 그 소리가 나온다. 글자와 소리를 나란히 놓고 보면 인식이 맞았는지 학생도 판단할 수 있다
5. **고치기** — 잘못 인식된 곳이 있으면 수정을 눌러 그 자리에서 고친다. 수정 완료를 누르면 큰 글자 화면으로 돌아온다. 고친 뒤 읽어주기를 누르면 고치기 전 소리가 나오므로, 학생에게 무엇이 달라졌는지 짚어 주기 좋다
6. **기록하기** — 기록하기를 누르면 그때 저장된다. 화면이 비워지고 다음 학생 차례로 넘어간다
7. **화자 전환** — 다음 학생의 칩을 누른 뒤 다시 마이크를 누른다
8. **버리기** — 인식이 크게 틀렸으면 지우기를 눌러 기록하지 않고 버린 뒤 다시 말하게 한다
9. **수업 후** — 목록 탭 → CSV 또는 JSON 내보내기 → 학생 파일에 보관

### 개인정보 보호 권고

- 학생 실명 대신 `학생 1`, `A`, 학번 등 **익명 코드** 사용을 권장합니다.
- 기록 원본은 교내 규정에 따른 보관 장소(학교 서버, 암호화 저장 장치)로 옮기고, 태블릿 브라우저의 기록은 주기적으로 삭제하십시오.
- 발화 기록을 연구 자료로 사용할 경우 보호자 동의와 기관생명윤리위원회(IRB) 절차를 선행하십시오.

## 6-1. 입력 방식 세 가지

설정 패널에서 고릅니다.

| 방식 | 동작 | 적합한 상황 |
|---|---|---|
| 버튼을 누르는 동안만 녹음 (기본) | 누른 동안만 녹음하고, 기록하기를 눌러야 저장 | 한 명씩 차례로 말하는 수업, 확인·수정 절차가 필요한 경우 |
| 계속 녹음 — 자동 넘김 | 한 문장이 끝나도 화면에 남고 다음 발화가 오면 앞 발화를 자동 기록. 30초 상한 적용 | 발화가 빠르게 이어지는 집단 활동 |
| 계속 녹음 — 이어 쌓기 | 말한 내용이 화면에 계속 쌓이고 기록하기로 한 건 저장 | 긴 이야기를 한 건으로 남길 때 |

누르고 말하기 방식은 키보드로도 쓸 수 있습니다. 마이크 버튼에 초점을 둔 뒤 스페이스바나 엔터를 누르고 있으면 녹음되고, 떼면 멈춥니다.

## 6-2. 소리로 확인하기 — 학생 본인 목소리만 사용

소리는 모두 학생이 실제로 말한 녹음입니다. 기계 음성(음성 합성)은 쓰지 않습니다.

| 버튼 | 소리 | 속도 | 쓰임 |
|---|---|---|---|
| 내 목소리 듣기 | 그 발화의 녹음 | 보통(1배) | 인식 결과와 자기 말을 맞춰 보기 |
| 천천히 반복 | 같은 녹음 | 0.5~0.8배 (기본 0.7배) | 조음을 살피며 여러 번 듣기 |

두 버튼 모두 녹음이 있을 때만 활성화됩니다. 키보드로만 입력한 기록에는 소리가 없으므로 비활성 상태로 남습니다.

천천히 반복은 버튼에 진행 횟수가 "3/10회" 형태로 표시되고, 다시 누르면 언제든 멈춥니다. 설정한 횟수를 채우면 자동으로 멈춥니다. 반복 횟수는 5 / 10 / 15 / 20회 중에 고르며 기본은 10회입니다.

속도를 늦출 때 목소리의 높낮이는 그대로 둡니다(`preservesPitch`). 그래서 느리게 들어도 같은 학생의 목소리로 들리며, 조음 동작을 살피기 좋습니다.

목록 탭의 각 기록에도 듣기와 천천히 버튼이 붙습니다. 수업 중에는 기록 화면에서, 수업 뒤 복기할 때는 목록에서 씁니다.

### 앱이 내는 소리는 모두 학생의 실제 발화입니다

이 표의 두 버튼도, 6-4의 낱말 모델도 학생이 실제로 낸 소리입니다. 글자와 소리가 항상 같은 발화에서 나오므로 오인할 여지가 없습니다.

교사가 고친 글을 학생 목소리로 새로 만들어 들려주는 합성 기능은 비용 문제로 앱에서 제외했습니다. 6-5를 보십시오.

## 6-3. 학생 목소리 녹음

마이크 버튼을 누르고 있는 동안의 음성을 함께 담습니다. 누르고 말하기 방식이라 발화 구간이 정확히 한 조각으로 떨어집니다.

| 항목 | 값 |
|---|---|
| 형식 | `audio/webm;codecs=opus` (미지원 기기는 `audio/mp4`) |
| 품질 | 기본 16kbps 단일 채널. 24 / 32kbps 선택 가능 |
| 실측 용량 | 2.2초 발화가 약 3.6KB. 초당 약 1.7KB |
| 보관 위치 | 이 기기의 IndexedDB. 서버로 전송하지 않음 |
| 보관 시간 | 1시간 고정. 설정 선택지 없음. 1분마다 검사해 지난 음성을 자동 삭제 |
| 화자별 켜고 끄기 | 설정의 화자 목록에서 학생마다 전환. 켜진 학생은 칩에 ● 표시 |
| 녹음 중 표시 | 자막 위 빨간 테두리 패널에 화자 이름과 실시간 입력 크기 막대 |
| 내보내기 | 없음. 파일로 저장하거나 전송하는 기능을 두지 않았습니다 |

버튼이 두 개이고 역할이 다릅니다.

| 버튼 | 하는 일 | 저장 |
|---|---|---|
| 누르고 말하기 | 음성 인식(글자) + 목소리 녹음 | 기록하기를 누르면 글자와 소리를 함께 저장 |
| 목소리 녹음 | 글자 인식 없이 목소리만 담기 | 이 기기에 1시간 보관. 듣기·낱말 고르기·이어 읽기에 사용 |

목소리 녹음 버튼은 두 가지 일을 합니다. 누르고 있는 동안 자막 위에 빨간 테두리와 함께 "녹음 중 — OOO 말해 보세요" 표시가 뜨고, 옆의 막대가 목소리 크기에 따라 실시간으로 움직입니다. 학생이 자기 목소리가 기계에 닿고 있다는 것을 눈으로 확인할 수 있어, 발화를 주저하는 학생에게 말할 차례임을 알리는 신호로 쓸 수 있습니다.

동시에 그 소리를 담아 둡니다. 글자 인식은 하지 않으므로 기록에 글이 남지 않지만, 담은 소리는 내 목소리 듣기·천천히 반복·낱말 고르기·이어 읽기에 그대로 쓰입니다. 인식이 어려운 학생의 발음을 다루거나, 글은 교사가 수정으로 직접 넣고 소리만 학생에게서 받을 때 이 순서가 편합니다.

| 쓰는 순서 | 내용 |
|---|---|
| 1 | 🔴 목소리 녹음을 누른 채 학생이 말합니다 |
| 2 | ✏️ 수정으로 읽을 글을 직접 넣습니다 |
| 3 | ✂️ 낱말 고르기로 낱말이나 음절을 잘라 저장합니다 |
| 4 | 🗣️ 이어 읽기로 그 글을 학생 목소리로 읽어 줍니다 |

너무 짧게 누르면 소리가 담기지 않고 안내가 뜹니다. 담은 소리도 1시간 뒤 자동으로 지워집니다.

녹음이 꺼진 학생은 두 방법 모두에서 목소리가 담기지 않고 글자만 기록됩니다. 자기 목소리를 듣기 불편해하는 학생이나 보호자 동의를 받지 못한 학생은 꺼 두십시오.

재생은 읽어주기 버튼이 맡습니다. 기록 화면에서는 방금 녹음한 음성을, 목록에서는 보관 중인 음성을 재생합니다. 보관 시간이 지나 음성이 사라지면 버튼 표시가 기계 음성으로 바뀌고 글자 기록은 그대로 남습니다.

설정에서 언제든 녹음을 끄거나 "지금 음성 모두 삭제"로 보관 중인 음성을 즉시 비울 수 있습니다. 현재 보관량은 설정 화면에 개수와 용량으로 표시됩니다.

### 개인정보 유의사항

학생의 음성은 개인정보보호법상 개인정보에 해당하며, 글자 기록보다 민감하게 다뤄야 합니다. 이 앱은 다음 장치를 두었습니다.

- 마이크를 누르고 있는 동안에만 녹음되므로 의도하지 않은 녹음이 남지 않습니다
- 학생마다 녹음을 끌 수 있어, 보호자 동의를 받은 학생에게만 적용할 수 있습니다
- 짧은 보관 시간을 기본값으로 두고 자동 삭제합니다
- 파일 내보내기 기능이 없어 기기 밖으로 나갈 경로가 없습니다

운영 시에는 화자를 실명 대신 익명 코드로 등록하시고, 연구 자료로 활용하실 경우 보호자 동의와 기관생명윤리위원회 심의를 먼저 받으십시오.

### 인식률 분석과의 관계

교정 사전과 수동 수정만으로 산출한 오인식률은 교사가 알아차린 경우만 잡히므로 하한값입니다. 보관 시간 안에 원음을 다시 들으며 인식 결과와 대조하면, 표본 회기에 한해 정확한 오류율을 산출할 수 있습니다.

## 6-4. 낱말 고르기 — 편집형 자기 모델링

학생이 바르게 낸 낱말 하나를 녹음에서 잘라 모델로 남기는 기능입니다. 합성이 아니라 학생이 실제로 낸 소리이므로, 자기 모델링 연구가 검증한 방식(정반응 편집본 관찰)이 그대로 적용됩니다. 외부 서비스도, 비용도, 추가 동의도 필요 없습니다.

### 쓰는 순서

1. 마이크를 누르고 학생이 말합니다. 여러 번 시도하다 한 번 바르게 나온 순간이 목표입니다.
2. 하단의 ✂️ 낱말 고르기를 누릅니다.
3. 화면 글자가 낱말 단추로 나뉘어 나옵니다. 목표 낱말을 고릅니다. 목록에 없으면 직접 입력 후 지정을 누릅니다.
4. 시작·끝 손잡이로 구간을 좁힙니다. ▶ 구간 들어 보기와 🐢 느리게로 확인합니다.
5. 💾 낱말 모델로 저장을 누릅니다.
6. 📚 낱말 모델에서 언제든 듣기·천천히로 다시 들려줍니다.

### 기술 구현

녹음은 `audio/webm;codecs=opus` 라 그대로 자를 수 없습니다. Web Audio 로 디코드한 뒤 지정 구간의 표본만 떼어 16비트 PCM WAV 로 다시 씁니다(외부 라이브러리 없음). 0.8초 구간이 약 25KB 입니다.

### 학생별로 구분해 관리합니다

낱말 모델은 저장할 때 그 시점의 화자로 기록됩니다.

- 낱말 모델 화면 위쪽에 학생 칩이 나오고 칩마다 개수가 표시됩니다. 전체 칩을 누르면 모든 학생을 학생별 머리글로 묶어 보여 줍니다.
- 화면을 열면 지금 고른 학생이 자동으로 선택됩니다. 수업 중에 바로 그 학생 것만 보게 하려는 설계입니다.
- 삭제 버튼은 고른 학생의 모델만 지웁니다. 전체 칩을 고른 상태에서 누르면 전부 지웁니다.
- 낱말 고르기 화면 제목에 현재 학생 이름이 표시되어, 다른 학생 이름으로 저장되는 실수를 줄입니다.

### 음절로 나누어 저장하기

낱말 고르기 화면에서 🔡 음절로 나누기를 누르면, 고른 구간을 낱말의 음절 수만큼 자동으로 나눕니다. 나누는 지점은 소리 크기(RMS)가 가장 작아지는 곳을 찾아 정합니다. 10ms 간격으로 소리 크기를 재고 3점 평활한 뒤, 균등 분할 지점 주변에서 가장 조용한 곳으로 경계를 붙입니다.

각 음절은 ◀ ▶ 로 경계를 0.03초씩 옮기고 🔊 로 들어 보며 확인합니다. 저장하지 않을 음절은 건너뜀으로 바꿉니다. 경계는 항상 빈틈없이 이어지므로 앞 음절의 끝이 뒤 음절의 시작이 됩니다.

음절을 모아 두면 처음 보는 낱말도 읽을 수 있습니다. 한국어는 음절 단위로 적히므로, "바다"와 "조개"에서 나온 네 음절이 다른 낱말에서도 재사용됩니다.

### 이어 읽기 — 화면의 글을 학생 목소리로 읽어 주기

🗣️ 이어 읽기는 큰 화면의 글을 그 학생이 실제로 낸 소리로 읽어 줍니다. 연결 합성(concatenative synthesis) 방식이며, 신경망 음성 복제와 달리 재료가 전부 학생의 실제 발화입니다.

어절마다 다음 순서로 읽을 방법을 정합니다.

| 순서 | 방법 | 표시 |
|---|---|---|
| 1 | 낱말 모델이 완전히 일치 | 표시 없음 |
| 2 | 낱말 모델이 앞부분과 일치하고 나머지를 음절로 채움 | ·혼합 |
| 3 | 앞부분만 일치하고 나머지 음절이 없으면 어간만 | ·일부 |
| 4 | 모든 음절이 있으면 음절만으로 | ·음절 |
| 5 | 그 외 | 줄이 그어짐 (건너뜀) |

| 화면 표시 | 뜻 |
|---|---|
| 초록 테두리 어절 | 소리가 납니다 |
| 초록 배경 어절 | 지금 소리가 나고 있습니다 |
| 줄이 그어진 어절 | 모델이 없어 건너뜁니다 |

표시줄 오른쪽에 "9/12 어절 읽기 가능 · 빠진 음절: 웠 주"처럼 커버리지와 부족한 음절이 나옵니다. 무엇을 더 녹음해야 하는지 바로 알 수 있습니다.

소리는 어절마다 조각을 이어 붙여 만들고, 음절 사이는 12ms 겹쳐 이음새를 줄이며 어절 사이에는 160ms 쉼을 둡니다. 문장 전체를 하나의 소리로 합쳐 한 번에 재생하므로 조각 재생보다 자연스럽습니다.

버튼은 그 학생의 모델이 문장 안에 하나라도 있을 때만 활성화됩니다. 재생 중 다시 누르면 멈춥니다. 모델은 학생별로 구분되므로 화자를 바꾸면 그 학생의 모델만 씁니다.

한계를 분명히 적습니다. 이어 붙인 소리는 운율이 어색합니다. 억양과 속도가 조각마다 달라 기계적으로 들립니다. 다만 자기 모델링 목적에서는 학생이 실제로 낸 소리라는 점이 신경망 합성보다 유리합니다.

모델은 1시간 뒤 지워지므로 이어 읽기도 그 시간 안에서만 동작합니다. 한 회기에서 자주 쓰는 음절을 모을수록 읽을 수 있는 범위가 넓어집니다.

### 보관 시간 — 1시간 고정

녹음과 낱말 모델 모두 만든 때부터 1시간 뒤 자동으로 지워집니다. 이 값은 상수로 고정되어 있어 설정 화면에 선택지가 없습니다.

| 항목 | 내용 |
|---|---|
| 보관 위치 | 이 기기의 IndexedDB. 서버로 보내지 않음 |
| 보관 시간 | 1시간 고정. 설정으로 늘리거나 줄일 수 없음 |
| 자동 삭제 | 1분마다 검사해 시간이 지난 모델을 지우고 목록에서도 제거 |
| 남은 시간 | 목록의 각 항목에 "○○분 뒤 자동 삭제"로 표시 |
| 내보내기 | 대상이 아님. CSV·JSON·TXT 어디에도 들어가지 않음 |

다음 수업에 다시 쓰시려면 그때 다시 만드셔야 합니다. 이 제약은 학생 음성이 기기에 오래 남지 않게 하려는 설계이며, 임의로 늘리지 않았습니다.

## 6-5. 음성 복제(유료) — 현재 앱에서 사용하지 않습니다

학생 목소리를 복제해 임의의 문장을 읽어 주는 기능은 검토했으나 앱에서 제외했습니다. 이유는 비용입니다.

| 요금제 | 음성 복제 |
|---|---|
| ElevenLabs Free (월 10,000 크레딧) | 없음. 고정 화자 합성만. 상업적 이용 권한도 없음 |
| ElevenLabs Starter (월 6달러) | 즉시 음성 복제 포함 |
| ElevenLabs Creator | 전문 음성 복제 포함 |

무료로 쓸 수 있는 것은 Cloudflare Workers 중계 계층뿐이며, 합성 서비스 구독료는 별도입니다. 이 앱은 무료 범위 안에서만 동작하도록 정리했으므로, 합성 관련 버튼과 설정은 화면에 없습니다. 앱은 어떤 외부 서버에도 요청을 보내지 않습니다.

저장소의 `worker.js` 와 `wrangler.toml` 은 나중에 유료 전환을 검토하실 때를 위해 남겨 두었습니다. GitHub Pages 배포와는 무관한 파일이며, 올리지 않아도 앱은 정상 동작합니다.

교육적으로도 6-4의 낱말 고르기가 우선입니다. 자기 모델링 연구가 검증한 것은 학생이 실제로 산출한 정반응을 편집해 보여 주는 방식이고, 합성 음성 모델의 중재 효과를 직접 검증한 연구는 확인되지 않았습니다.

## 7-1. 오인식 낱말 교정과 인식률 분석

### 교정 규칙 등록

설정 패널의 "자주 틀리는 말 교정"에서 잘못 인식되는 말과 올바른 말을 한 쌍씩 등록합니다. 이후 인식된 모든 문장에 등록 순서대로 자동 적용됩니다.

| 예시 상황 | 잘못 인식되는 말 | 올바른 말 |
|---|---|---|
| 학생 이름이 일반 낱말로 바뀔 때 | 서연이 | 이서연 |
| 교과·활동명이 비슷한 발음으로 바뀔 때 | 국어 시간 | 국악 시간 |
| 조음 오류가 일정한 형태로 나타날 때 | 체윤 | 체육 |
| 학교 고유 명칭이 인식되지 않을 때 | 위덕 초등학교 | 위덕대학교 부설학교 |

규칙은 단순 문자열 치환입니다. 짧은 낱말을 등록하면 뜻하지 않은 곳까지 바뀔 수 있으므로, 가능한 한 앞뒤 맥락을 포함한 형태로 등록하십시오.

### 원문 보관 방식

교정이 적용된 기록에는 바뀌기 전 인식 원문이 `raw` 로 함께 저장되고, 목록에 "인식 원문" 줄로 표시됩니다. 교사가 손으로 고친 경우에도 최초 수정 시점의 인식 결과가 같은 방식으로 보관됩니다. 따라서 교정본과 실제 인식 결과를 항상 대조할 수 있습니다.

### 분석 지표 읽는 법

통계 탭의 "인식 교정 분석"이 네 가지를 보여 줍니다.

| 지표 | 의미 |
|---|---|
| 음성 인식 발화 수 | 분석 대상 모수 (직접 입력 건은 제외) |
| 자동 교정이 적용된 발화 | 등록한 규칙이 걸린 발화의 수와 비율 |
| 교사가 손으로 고친 발화 | 규칙으로 잡히지 않아 사람이 개입한 발화의 수와 비율 |
| 손질이 필요했던 발화 비율 | 위 둘을 합친 비율 |

주의할 점이 있습니다. 이 비율은 교사가 알아차리고 손을 댄 경우만 집계하므로, 실제 오인식률의 하한으로 읽어야 합니다. 교사가 넘어간 오인식은 잡히지 않습니다. 정확한 오인식률을 산출하시려면 표본 회기를 정해 모든 발화를 검토한 뒤 CSV의 내용 열과 인식 원문 열을 대조하십시오.

규칙별 표에는 적용 횟수와 마지막 적용일이 나옵니다. 적용 0회인 규칙은 등록한 표현이 실제 인식 결과와 다르다는 신호이므로, 기록의 인식 원문을 보고 표현을 다듬으십시오.

### 내보내기

CSV에 인식 원문, 자동 교정 횟수, 교사 수정 열이 포함됩니다. JSON 내보내기에는 교정 규칙과 적용 횟수가 함께 담겨, 다른 기기로 옮기면 규칙까지 그대로 이어집니다.

## 8. 교육적 설계 근거

보편적 학습 설계(UDL) 관점에서 다음과 같이 대응했습니다.

| UDL 원리 | 이 앱의 구현 |
|---|---|
| 표상(Representation) — 다양한 방식의 정보 제시 | 12~100pt 글자 크기 조절, 고대비 테마 4종, 전체화면형 자막, 같은 내용을 소리로 다시 듣는 읽어주기 |
| 행동과 표현(Action & Expression) — 다양한 방식의 표현 | 음성 입력과 키보드 입력 병행, 인식 결과 즉시 수정, 학생 개인의 조음 특성에 맞춘 교정 규칙 등록 |
| 참여(Engagement) — 난이도 조절 | 발음 연습 속도를 학생에 맞춰 0.5~0.8배로 조절, 반복 횟수를 교사가 통제 |
| 인식(Recognition) — 자기 발화의 다중 확인 경로 | 같은 발화를 글자로 보고, 본인 목소리로 듣고, 기계 음성으로 들어 세 경로로 확인 |
| 참여(Engagement) — 다양한 방식의 참여 유도 | 자기 발화가 큰 글자로 나타나 다음 발화 때까지 유지되므로, 학생이 자기 말을 충분히 읽고 확인할 시간을 확보. 화자별 통계로 참여량 확인 |

수집된 화자별 발화 횟수·길이 자료는 개별화교육계획(IEP)의 의사소통 영역 현행 수준 기술과 목표 도달 여부 점검에 **형성적 자료**로 활용할 수 있습니다.

## 9. 알려진 제한점

- 지원 대상은 갤럭시(안드로이드) 태블릿의 Chrome 입니다. 아이패드·아이폰은 지원하지 않으며, 접속 시 안내 배너가 뜹니다.
- 브라우저 내장 음성 인식은 **조음 명료도가 낮은 발화의 인식률이 떨어집니다.** 구어 명료도가 낮은 학생에게는 인식 결과를 그대로 신뢰하지 말고 교사 확인·수정 절차를 반드시 두십시오. 발화가 화면에 유지되는 동안 교사가 확인하고, 잘못되었으면 지우기로 버릴 수 있습니다.
- 동시에 여러 명이 말하면 화자를 자동으로 구분하지 못합니다. 화자 칩을 수동으로 전환하는 방식입니다.
- 인식 엔진이 브라우저 제조사 서버를 사용하므로 오프라인에서는 동작하지 않습니다.
- 브라우저 저장 용량(약 5MB)을 초과하면 저장에 실패합니다. 화면 하단 설정 패널에서 현재 사용량을 확인할 수 있습니다.
